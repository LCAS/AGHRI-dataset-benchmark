# Camera-LiDAR Human Detection Fusion Workflow

This is the workflow for human detection with camera-guided LiDAR fusion in ROS 2 Humble. It covers the path from YOLO11s fine-tuning, numerical metric evaluation, ROS 2 bag conversion, replay, and RViz2 visualisation.

Numerical results come from the offline evaluator. ROS 2 bag replay and RViz2 are for qualitative inspection and end-to-end demonstration.

## 1. Overview

The final comparison has two detector checkpoints:

- Generic pretrained YOLO11s
- AGHRI fine-tuned YOLO11s

Both use the same fixed camera-LiDAR fusion method. The detector sees only ZED RGB images. Fisheye images, ZED depth, and LiDAR are not used during detector training.

## 4. Why ZED RGB Is Used

The detector is trained and evaluated on `cam_zed_rgb` only. The fusion node projects Livox points into the ZED RGB camera frame using the AGHRI calibration parameters, then publishes an annotated RGB result image.

## 5. Dataset Preparation

## 10. ROS 2 Test-Bag Conversion

The ROS 2 demonstration bags are generated by the AGHRI dataset-tools converter, so playback includes all dataset topics, labels, sensor streams, ZED and fisheye CameraInfo, dynamic `/tf`, and static sensor transforms written by:

```text
<dataset_tools_repo>/ros2bag/check_and_make_rosbag2.py
```

The fusion repository keeps `tools/convert_aghri_test_to_rosbags.py` as a thin wrapper around that converter for the six official held-out test recordings. The wrapper passes `--write-calibration`, so the calibration parameters are translated automatically into:

```text
/dataset/cam_zed_rgb/camera_info
/dataset/cam_fish_front/camera_info
/dataset/cam_fish_left/camera_info
/dataset/cam_fish_right/camera_info
/tf
/tf_static
```

The converter preserves the original image and LiDAR timestamps. It does not force ZED RGB and Livox messages to the same timestamp.

Dry run:

```bash
cd "${FUSION_REPO}"
/usr/bin/python3 tools/convert_aghri_test_to_rosbags.py \
  --dataset-root "${DATASET_ROOT}" \
  --test-manifest "${TEST_MANIFEST}" \
  --dataset-tools-root "${DATASET_TOOLS_REPO}" \
  --output-root "${ROSBAG_ROOT}" \
  --dry-run \
  --all-recordings
```

Convert one recording:

```bash
/usr/bin/python3 tools/convert_aghri_test_to_rosbags.py \
  --dataset-root "${DATASET_ROOT}" \
  --test-manifest "${TEST_MANIFEST}" \
  --dataset-tools-root "${DATASET_TOOLS_REPO}" \
  --output-root "${ROSBAG_ROOT}" \
  --recording "footpath1_p1_oj+mk+gl_1walk+check_st_11_12_2024_1_label" \
  --overwrite
```

The equivalent dataset-tools command for that recording is:

```bash
/usr/bin/python3 "${DATASET_TOOLS_REPO}/ros2bag/check_and_make_rosbag2.py" \
  --bag-dir "${DATASET_ROOT}/dataset_part1/footpath1_p1_oj+mk+gl_1walk+check_st_11_12_2024_1_label" \
  --make-rosbag \
  --rosbag-out "${ROSBAG_ROOT}/footpath1_p1_oj+mk+gl_1walk+check_st_11_12_2024_1_label" \
  --write-tf \
  --tf-parent map \
  --tf-child base_link \
  --tf-xyzrpy 0,0,0,0,0,0 \
  --write-calibration \
  --calibration-path "${DATASET_ROOT}/calibration.zip" \
  --intrinsics-member calibration/intrinsics.json \
  --extrinsics-member calibration/extrinsics.json \
  --camera-name cam_zed_rgb \
  --camera-info-topic /dataset/cam_zed_rgb/camera_info \
  --camera-info-cameras cam_zed_rgb,cam_fish_front,cam_fish_left,cam_fish_right
```

Convert all six official test recordings:

```bash
/usr/bin/python3 tools/convert_aghri_test_to_rosbags.py \
  --dataset-root "${DATASET_ROOT}" \
  --test-manifest "${TEST_MANIFEST}" \
  --dataset-tools-root "${DATASET_TOOLS_REPO}" \
  --output-root "${ROSBAG_ROOT}" \
  --all-recordings \
  --overwrite
```

## 11. Bag Verification

```bash
/usr/bin/python3 tools/verify_aghri_test_rosbags.py \
  --dataset-root "${DATASET_ROOT}" \
  --test-manifest "${TEST_MANIFEST}" \
  --bag-root "${ROSBAG_ROOT}" \
  --all-recordings
```

Verification outputs:

```text
<rosbag_root>/bag_manifest.csv
<rosbag_root>/bag_manifest.json
<rosbag_root>/verification_summary.json
```

The verifier checks that each full-topic dataset-tools bag opens, required topics exist, message counts match the manifest, ZED RGB and fisheye images and CameraInfo have one-for-one timestamps, frame IDs are calibrated, `/tf` contains `map -> base_link`, `/tf_static` is present, tf2 resolves `front_lidar_link` to `front_left_camera_optical_frame`, the resolved transform matches the calibration extrinsics, timestamps are monotonic, and enough image/cloud messages fall within the configured 0.10 s approximate synchronization tolerance.

## 16. Topic Reference

Input topics:

| ROS 2 topic | Message type | Frame |
| --- | --- | --- |
| `/dataset/cam_zed_rgb/image` | `sensor_msgs/msg/Image` | `front_left_camera_optical_frame` |
| `/dataset/cam_zed_rgb/camera_info` | `sensor_msgs/msg/CameraInfo` | `front_left_camera_optical_frame` |
| `/dataset/cam_fish_front/image` | `sensor_msgs/msg/Image` | `fish_front_camera_link_optical` |
| `/dataset/cam_fish_front/camera_info` | `sensor_msgs/msg/CameraInfo` | `fish_front_camera_link_optical` |
| `/dataset/cam_fish_left/image` | `sensor_msgs/msg/Image` | `fish_left_camera_link_optical` |
| `/dataset/cam_fish_left/camera_info` | `sensor_msgs/msg/CameraInfo` | `fish_left_camera_link_optical` |
| `/dataset/cam_fish_right/image` | `sensor_msgs/msg/Image` | `fish_right_camera_link_optical` |
| `/dataset/cam_fish_right/camera_info` | `sensor_msgs/msg/CameraInfo` | `fish_right_camera_link_optical` |
| `/dataset/lidar/points` | `sensor_msgs/msg/PointCloud2` | `front_lidar_link` |
| `/tf` | `tf2_msgs/msg/TFMessage` | dynamic `map -> base_link` |
| `/tf_static` | `tf2_msgs/msg/TFMessage` | static sensor transforms |

The preferred AGHRI fusion configs use:

```yaml
calibration_mode: "ros_camera_info_tf"
camera_info_topic: "/dataset/cam_zed_rgb/camera_info"
camera_matrix_source: "p"
sync_mode: "approximate"
sync_queue_size: 30
sync_slop_sec: 0.10
```

In this mode the fusion node reads `CameraInfo.p`, resolves `front_lidar_link` to `front_left_camera_optical_frame` through tf2, and builds the Livox-to-ZED projection matrix used for image overlay and 3D association.

The launch file passes:

```text
--qos-profile-overrides-path <fusion_repo>/config/aghri_rosbag2_qos_overrides.yaml
```

so rosbag2 playback publishes `/tf_static` with transient-local durability on ROS 2 Humble.

Ground-truth annotation topics are present in the bag for inspection, but the ROS/RViz playback path does not require ground truth. The final numerical results come from the separate offline evaluator, which reads the native AGHRI files directly.

Output topics:

| ROS 2 topic | Message type | Contents |
| --- | --- | --- |
| `/camera_lidar_fusion/result` | `sensor_msgs/msg/Image` | Annotated image with detector boxes, projected LiDAR points, and distance text when enabled |
| `/camera_lidar_fusion/pred_bboxes` | `std_msgs/msg/String` | Detector boxes and associated 3D camera-frame values |

For the AGHRI RViz configs, `coordinate_label_mode: "depth"` makes the image label show only the camera-frame depth, for example `person : 5.33m`. The full 3D camera coordinate remains available on `/camera_lidar_fusion/pred_bboxes`.
